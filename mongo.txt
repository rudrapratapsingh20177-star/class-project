Exercise 2: CAP Theorem Analysis
For each scenario, identify which CAP properties are prioritized:
1. Stock trading platform
   ans: CP (Consistency + Partition Tolerance)
        Data must be accurate and up-to-date (no wrong trades)
        Network failures can happen → must tolerate partitions
        Availability can be sacrificed (better to delay than show wrong price)
2. Content delivery network
   ans: AP (Availability + Partition Tolerance)
        Content (videos, images) should always be accessible
        Slightly outdated data is acceptable (cache)
        Strong consistency is not required
3. Airline booking system
   ans: Airline Booking System → CP (Consistency + Partition Tolerance)
        Seat booking must be accurate (no double booking)
        System must handle network issues
        Availability may be reduced (temporary booking failure is okay)
4. Video streaming service
   ans:Video Streaming Service → AP (Availability + Partition Tolerance)
       Users expect continuous streaming
       Slight delay or lower quality (inconsistency) is acceptable
       Strict consistency not required

Explain the key differences between SQL and NoSQL databases with examples.

1. SQL Databases

SQL databases are relational databases that store data in the form of tables (rows and columns). They use a fixed structure (schema), which means the format of data must be defined before storing it.

Examples: MySQL, PostgreSQL

Example:
A table storing user data:

ID | Name | Age
1 | John | 25

SQL query example:
SELECT * FROM Users WHERE age > 20;

NoSQL Databases

NoSQL databases are non-relational databases that store data in flexible formats like documents, key-value pairs, or graphs. They do not require a fixed schema, so data can be stored in different structures.

Examples: MongoDB, Redis

Example:
A document in MongoDB:
{
  "name": "John",
  "age": 25
}
Query example:
db.users.find({ age: { $gt: 20 } })

What does the CAP theorem state, and why can’t a distributed system guarantee all three
properties?
The CAP Theorem states that a distributed system can provide only two out of three properties at the same time:

Consistency (C): All users see the same data
Availability (A): System always responds
Partition Tolerance (P): System works even if network fails

Why not all three?
When a network failure (partition) happens, the system must choose:

Either give correct data (Consistency)
Or give response quickly (Availability)

It cannot guarantee both at the same time during failure.

 Why does MongoDB use BSON internally instead of storing documents as JSON?
 MongoDB uses BSON because:

Faster processing (binary format is quicker to parse)
Supports more data types (Date, ObjectId, etc.)
More efficient storage and indexing

JSON is text-based, while BSON is optimized for performance.

1. What are the advantages of using Mongoose over the native MongoDB driver?
1. Advantages of using Mongoose

Mongoose is easier to use than the native MongoDB driver because:

Provides schema-based structure (better organization)
Built-in validation (e.g., required fields)
Supports middleware (hooks)
Easy data relationships using references
Cleaner and shorter code


2. Explain the difference between findOneAndUpdate() and updateOne().
findOneAndUpdate()

Finds and updates a document
Can return the updated document
Example:Model.findOneAndUpdate(
  { email: "test@gmail.com" },
  { gpa: 3.8 },
  { new: true }
)
updateOne()

Only updates the document
Returns update status, not the document
Model.updateOne(
  { email: "test@gmail.com" },
  { $set: { gpa: 3.8 } }
)



3. What is the purpose of middleware in Mongoose?
Middleware (also called hooks) are functions that run before or after database operations.

Used for:

Validation
Logging
Password hashing

Example:schema.pre("save", function(next) {
  console.log("Before saving data");
  next();
});



4. How do you implement pagination in Mongoose?
Pagination is used to limit and skip data for large datasets.
const page = 1;
const limit = 10;

Model.find()
  .skip((page - 1) * limit)
  .limit(limit);



5. When should you use embedding vs referencing in MongoDB schema design?
Embedding
Store data inside one document
Faster read
Use when data is small and related
{
  "name": "Rudra",
  "courses": ["CS101", "CS102"]
}

Referencing
Store data in separate collections using IDs
Avoids duplication
Use when data is large or shared
{
  "studentId": "123",
  "courseId": "456"
}
